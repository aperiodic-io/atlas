Atlas · Open source · MIT · Updated {{generated_day}}

One ID for every real-world asset, on every venue.

Atlas is a free, open-source security master for real-world-asset and crypto perpetuals. It maps every equity, commodity, FX, index, pre-IPO and crypto contract on {{venue_groups}} CEX and DEX venues (Hyperliquid HIP-3, Avantis, Lighter, GRVT, Aster, Variational, Binance, Bybit, OKX and more) to one normalized ID and one Atlas asset. It keeps the delisted contracts, and it refreshes itself every day.

The problem

Same market, different names

Real-world assets have tickers, ISINs and exchanges of record. Their perpetuals do not. Every venue invents its own scheme: one names {{example_ticker}} by ticker, another by a numeric market index, a third behind a deployer's dex: prefix. The same ticker can also mean a stock on one venue and an unrelated token on the next.

Join them by hand and the code works until it silently doesn't. Atlas does the mapping once, in the open, for everyone: each contract gets an Atlas ID, and each asset an Atlas asset ID that is the same on every venue.

The symbology

Two IDs: the contract and the asset

The Atlas ID (internal_id) names the contract as the venue lists it. It is lossless, so it maps back to the venue's own instrument.

<type>-<symbol>-<denominator>[:<margin>][-<yyyymmdd>]

The unified ID writes the same contract in Atlas asset IDs, so it reads the same on every venue. Hyperliquid's xyz:TSLA and Bybit's TSLAUSDT both trade the asset TSLA.

type
spot, perpetual or future.
symbol
The base as the venue lists it. 1000PEPE stays 1000PEPE, and a HIP-3 dex keeps its prefix.
denominator
The quote or settlement currency the price is in.
:margin
The collateral asset. Derivatives only; it tells linear from inverse.
-yyyymmdd
The delivery date. Dated futures only.
underlying
equity, commodity, forex, index, pre_market or crypto, from the venue's own metadata.

Each record also holds the contract size, margin asset, asset class, the Atlas asset IDs of every leg and the listing window: first_capture and, once it stops trading, end_date.

Quick start

Local lookups, no key

Python 3.12 or later. The snapshots ship with the package, so every lookup is a local dictionary read with no network call.

shell
pip install git+https://github.com/aperiodic-io/atlas

Prefer plain data? Every snapshot is published as JSON next to this page, for example data/avantis-perps.json, and the whole catalogue as catalog/instruments.json.

example.py
from atlas import SecurityMaster

sm = SecurityMaster.load()  # bundled snapshots, no network

# One stock, three venues, three native names
sm.base_asset("hyperliquid-perps", "xyz:TSLA").asset_id   # 'TSLA'
sm.base_asset("bybit-perps-usd", "TSLAUSDT").asset_id   # 'TSLA'
sm.base_asset("binance-futures", "tslausdt").asset_id   # 'TSLA'

# Every venue that lists Tesla, live or delisted
sm.exchanges_for_asset("TSLA")

# Gold is XAU, whatever the venue calls it
sm.base_asset("hyperliquid-perps", "xyz:GOLD").asset_id   # 'XAU'

# The full record: class, contract size, margin, listing window
sm.instrument_metadata("avantis-perps", "11")
# {'symbol': 'EUR', 'underlying': 'forex', 'margin': 'USDC', ...}

Kept up to date, in public

A daily pipeline you can read

  1. 01

    Fetch

    Every day at 02:00 UTC a GitHub Action reads each venue's whole current universe from that venue's own public API, for centralized and decentralized venues alike.

  2. 02

    Merge

    New listings are parsed into Atlas IDs. Delistings get an end date, and fields a source stops sending are kept, not wiped.

  3. 03

    Resolve

    Each contract is matched to an Atlas asset. The evidence is CoinMarketCap's own venue listings, venue lineage and cross-venue consensus, with reference assets for stocks, commodities and indices.

  4. 04

    Publish

    The snapshots are committed to git, the tests guard every parser, and this site rebuilds from the new data.
